## NPPR build work

Before any NPPR build step, read NPPR-FRAMEWORK.md at the root of this vault. It holds the site structure, the page standard and the step-by-step build prompts. Follow these rules:

- BC sources first, then national Canadian sources, then others; label international guidance as such. In a sheet that order is the `region` rank: provinces and territories (BC first), then `CA`, then `US`, then `INTL`; a second region's sources go on the same sheet with their own code, never on a copy of the page.
- For approaches and condition pages, AAFP (aafp.org) is the first international source, free articles only. Don't link Specialist Link's Calgary pathway when Alberta's Pathway Hub (primarycarealberta.ca) has a pathway for the same condition.
- Before researching any page, check every site in the Source map table in NPPR-FRAMEWORK.md: the All topics row plus the row for that page's system or population.
- A promising source that would not open from the build environment (proxy denial, a site that blocks automated fetches, 403, 503, an empty page, a PDF whose text can't be read, or a page not found) is never dropped silently: add a row to UNOPENED-SOURCES.csv at the root of this vault (date, site, url, the page it was wanted for, what happened, the action: allowlist, hand check, find the right page or re-check later) and name it in the PR, so Joe can open it by hand or add the domain to the cloud environment's allowed list (Joe, 2026-11-05).
- Link to each publisher's own PDF only. Do not host or copy third-party documents.
- On condition pages, an entry's main link is the publisher's web page for the document, with its PDF on the same line, as on the approach pages: `- [Title (year)](web page) · [PDF](pdf link) — *note*`. Link the PDF alone only when no publisher page links to it. In the sources registry, record the web page as `url` and the PDF as `pdf`.
- No clinical recommendations in our own words: link to the source guidance instead.
- One current version of each source per page. When a guideline is replaced, change its row in `docs/sources.csv` (the sources registry: one row per document, with its title, publisher, url, pdf, year, region, kind and checked date, since 2026-11-05) and record the old version only in that row's `supersedes` field; superseded versions never appear in the page body. A sheet row names its document in the `source` column and leaves url, pdf and year blank for the registry to fill (`-` keeps a cell blank on purpose); a document on more than one page goes in the registry once. Pages carry no frontmatter `sources` list.
- One entry per guideline. Put its PDF, appendices and algorithm as sub-links under that entry, not as separate bullets, and don't link the same document from more than one section of a page.
- On condition pages, Key Sources holds only 1 to 3 sources: the BC Guideline first, then a more recent or broader national guideline, then one high-yield "approach to" or "management of" review. Every other source goes under `## Further Resources`, straight after Key Sources. When RxFiles has an appropriate resource for the condition, always link its RxFiles page in the Prescribing section, with a note when it needs a subscription (Joe, 2026-11-01).
- Show the year beside every guideline, algorithm and pathway in the page body.
- Always keep the BC Guidelines on a condition page, however old, and keep each one at its current version: when GPAC updates a guideline, replace the link and its year in its `docs/sources.csv` row, which every page that cites it reads.
- An Approaches page's list lives in the CSV list sheet beside the page (format: List sheets in NPPR-FRAMEWORK.md). Add, change or remove items in the sheet, never in the page, and keep the sheet in the page's order.
- A condition page's sections, Key Sources to Patient Resources, live in the CSV list sheet beside the page (`style=condition`, format: List sheets in NPPR-FRAMEWORK.md). Add, change or remove links in the sheet, never in the page; put each year in the registry's `year` column (or the sheet's, for a row with no `source`). Start new pages from NPPR - Condition.md and NPPR - Condition.csv.
- Assessments, Prescribing, Practice, Populations, Resources and Tools: AI Tools pages keep their sections in a `style=condition` CSV list sheet beside the page too (List sheets in NPPR-FRAMEWORK.md). Add, change or remove links in the sheet, never in the page. Start a new page of any type from its template and sheet in `03 Resources/Templates` (NPPR - Assessment, Practice, Prescribing, Resource, Population, Approach, each with its `.csv`): the Markdown holds frontmatter, comments, the filter box and the marker, and the intro line is the sheet's first row. Approaches pages alone keep their intro and More Approaches list in the page.
- Every sheet row that is a source carries a `region` code from `docs/regions.csv` (`BC`, `CA`, `INTL`, `ON`, `AB` ...): the jurisdiction its content is written for, not where its publisher sits; in frontmatter write `"ON"` in quotes, since YAML reads a bare `ON` as true. A row that is for its region alone (a referral or advice line, drug coverage, a regulator's standard, a province's own quality standard, forms, contacts, "How to do it" steps) gets `only=yes` as well, so it shows only when that region is picked: Ontario's quality standards and eConsult stay off the BC view, and RACE off Ontario's (Joe, 2026-11-05); guidance useful anywhere, such as CEP tools, leaves `only` blank. On a condition page the BC Key Sources rows are `only=yes`, each with a one-line copy at the top of Further Resources marked `only=other` (shown in every view but BC's), and the province's own key source goes in Key Sources with `only=yes` (for Ontario the Centre for Effective Practice tool when there is one, with its row elsewhere on the page marked `only=other`; the Ontario Health quality standards stay under Further Resources, Ontario only), so another province's view leads with its own tool and keeps the BC guideline under Further Resources (Joe, 2026-11-05). A new page is its frontmatter plus one sheet, nothing else in the Markdown (Regions and The page standard in NPPR-FRAMEWORK.md, since 2026-11-05).
- The Approaches section is a complete, accurate list of the "approach to" articles and pages each source offers, whatever their age. When a more recent guideline covers the same topic as an approach, keep the approach and add a link to that guideline, with its year, beside it.
- On condition pages, remove summaries and reviews (PEER, journal reviews) that predate the current version of the guideline they discuss, unless they cover something the guideline doesn't.
- When you add, move or remove a page, update the In This Section list on its section's index.md in the same change.
- Search is the site's key feature: keep it optimized. Give every new or renamed page its search aliases (abbreviations, drug and brand names, plain words) and its lines in scripts/search-checks.txt, add synonym groups for missed terms, mark text that repeats on every page `data-search-exclude`, and run `node scripts/search-check.js` (nppr-website-config) after the test build. Don't ship a change that fails it. Search is NPPR's own: keep frontmatter `type`, `system`, `jurisdiction`, `tags` and `aliases` and each sheet row's `year` and `pdf` accurate, because the search's filters, badges and results come from them; when a change adds a section, a sheet column or a list style, update `scripts/search_data.py` and `site_assets/nppr-search.js` in the same change; never add a generator search plugin or a second search box (Search and Keeping the search structure in NPPR-FRAMEWORK.md).
- Test-build the site and show the result before committing.
- Before opening any PR, run the Before every pull request list in NPPR-FRAMEWORK.md (the PR template repeats it as tick boxes) and tick what was done in the PR body.
- The build network is split over two cloud environments (Cloud environments in NPPR-FRAMEWORK.md; lists in `environments/`): name the one a wave or thread needs before it starts, Environment 1 for BC and Canadian work, Environment 2 for new condition pages, Ontario, international and pediatric sweeps; a site missing from the active one goes in UNOPENED-SOURCES.csv with action `allowlist: environment N` (Joe, 2026-11-05).
